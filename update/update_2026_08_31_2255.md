## Optimasi Frekuensi Fallback Polling Klien Antrian

### Masalah
Berdasarkan investigasi log Nginx produksi, perangkat klien dashboard antrian mengirimkan request GET /api/stats/Youth Center secara agresif sebanyak 2 kali per detik (setiap 500ms). Karena endpoint /api/stats menjalankan 5 kueri agregasi SQL per request, frekuensi polling ini membanjiri database MySQL dengan puluhan kueri per detik dan membebani resource server secara konstan.

### Penyebab
Nilai setInterval fallback polling pada file-file HTML frontend statis disetel ke 500 ms (0.5 detik). Padahal sistem sudah memiliki Server-Sent Events (SSE) sebagai jalur sinkronisasi real-time utama.

### Solusi
Menaikkan interval fallback polling menjadi 10000 ms (10 detik) pada seluruh halaman HTML statis antrian:
1. public/dashboard.html: interval fallback diubah dari 500ms menjadi 10 detik.
2. public/index.html: interval fallback diubah dari 500ms menjadi 10 detik.
3. public/public.html: interval fallback diubah dari 500ms menjadi 10 detik.
4. public/display.html: interval fallback diubah dari 5000ms menjadi 10 detik.

Jalur utama tetap menggunakan koneksi SSE (evtSource) yang langsung menerima notifikasi status antrian secara real-time tanpa penundaan. Fallback polling hanya berfungsi sebagai pengaman cadangan jika koneksi SSE terputus.
