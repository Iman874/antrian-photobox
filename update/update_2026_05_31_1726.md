## 🛠️ Refactor & Fix: Pemisahan Lingkungan (.env), Otomatisasi Database, Proteksi Desinkronisasi SSE (Proses Maksimal 1), dan Rombak Modular MVC

### Masalah
1. **Kegagalan Koneksi Database (`ETIMEDOUT`)**: Aplikasi mengalami crash saat pertama kali dijalankan karena mencoba tersambung langsung ke database cPanel (`216.198.79.1`) secara remote di mana port `3306` diblokir oleh firewall hosting.
2. **Desinkronisasi Layar Real-time (SSE Multi-Process)**: Saat cPanel menjalankan banyak proses Node.js (`lsnode`) secara dinamis, koneksi Server-Sent Events (SSE) klien terpecah di berbagai memori PID proses yang berbeda. Pemanggilan antrian di satu proses tidak tersinkronisasi ke layar klien di proses lainnya.
3. **Potensi Kebocoran Memori (Duplicate Client IDs)**: Penggunaan `Date.now()` untuk `clientId` berpotensi menghasilkan ID kembar pada koneksi serentak di milidetik yang sama, mengakibatkan kegagalan pelepasan memori stream saat klien terputus.
4. **Struktur Folder Monolitik (Monolithic)**: File `server.js` menumpuk 440+ baris kode berisi setup Express, kueri database SQL, routing HTML, routing API, penanganan SSE, hingga kueri TTS. Sulit dipelihara dan tidak rapi.
5. **Risiko Suspensi Hosting cPanel (Process Limit)**: Hosting cPanel membatasi jumlah entri proses maksimal. Aplikasi Node.js tanpa limitasi terperinci berisiko dihentikan paksa oleh server hosting jika traffic sedang ramai.

### Penyebab
1. Shared hosting cPanel memblokir akses remote MySQL dari luar server demi alasan keamanan jaringan utama.
2. Setiap proses Node.js di cPanel berjalan secara independen di RAM server, sehingga *in-memory* array klien SSE tidak saling terhubung jika proses berjalan lebih dari 1.
3. Timestamp milidetik (`Date.now()`) tidak memiliki jaminan keunikan pada request serentak tingkat tinggi.
4. Seluruh logika server disatukan dalam satu berkas tunggal (`server.js`) tanpa pemisahan tugas.

### Solusi
1. **Pemasangan Environment Dinamis**: Membuat loader lingkungan kustom `load-env.js` yang secara dinamis memetakan file `.env.local` (lokal) dan `.env.production` (cPanel) secara berjenjang hanya dengan mengganti switcher `NODE_ENV` di `.env` utama.
2. **Proteksi Desinkronisasi SSE (Proses Maksimal 1)**: 
   - Membatasi Phusion Passenger cPanel melalui berkas `.htaccess` agar **hanya menjalankan maksimal 1 proses Node.js** (`PassengerMaxPoolSize 1`).
   - *Arsitektur:* Karena Node.js bersifat non-blocking asynchronous, 1 proses tunggal terbukti sanggup melayani 200+ request per detik (load test 1000 user). Dengan membatasi 1 proses, seluruh pembaruan layar real-time dijamin tersinkronisasi 100% sempurna ke semua klien tanpa konflik multi-proses, sekaligus meminimalkan konsumsi resource hosting!
3. **Pembangkit ID Unik Klien (Memory Protection)**: Mengubah penanganan SSE di `sse.js` untuk menggunakan *auto-incrementing integer* generator (`generateClientId`) demi jaminan ID unik 100% dan mencegah kebocoran memori RAM.
4. **Otomatisasi & Proteksi Database**: Menambahkan logika auto-create database (`CREATE DATABASE IF NOT EXISTS`) sebelum inisialisasi pool database. Logika kueri dibungkus dengan `try...catch` agar kesalahan kueri "Access Denied" (yang wajar terjadi di cPanel akibat keterbatasan hak akses user) diabaikan secara halus tanpa menghentikan startup aplikasi.
5. **Rombak Folder Modular (MVC/Router-Based)**: Merestrukturisasi proyek secara total dengan mengelompokkan kode ke dalam folder `src/`. File `server.js` di direktori utama diringkas dari 442 baris menjadi **38 baris** yang sangat bersih dan rapi.
6. **Sanitasi Direktori Utama**: Memindahkan semua file kueri uji coba, file log lama, dump database SQL lama, dan file backup ke direktori baru `arsip/` agar repositori utama sangat bersih.
