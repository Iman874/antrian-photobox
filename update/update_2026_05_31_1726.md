## 🛠️ Refactor & Fix: Penyederhanaan .env (Standard dotenv), Otomatisasi Database, Limitasi Proses cPanel, dan Rombak Modular MVC

### Masalah
1. **Kegagalan Koneksi Database (`ETIMEDOUT`)**: Aplikasi mengalami crash saat pertama kali dijalankan karena mencoba tersambung langsung ke database cPanel (`216.198.79.1`) secara remote di mana port `3306` diblokir oleh firewall hosting.
2. **Struktur Folder Monolitik (Monolithic)**: File `server.js` menumpuk 440+ baris kode berisi setup Express, kueri database SQL, routing HTML, routing API, penanganan Server-Sent Events (SSE), hingga kueri TTS. Sulit dipelihara dan tidak rapi.
3. **Risiko Suspensi Hosting cPanel (Process Limit)**: Hosting cPanel membatasi jumlah entri proses maksimal. Aplikasi Node.js tanpa limitasi terperinci berisiko dihentikan paksa oleh server hosting jika traffic sedang ramai.

### Penyebab
1. Shared hosting cPanel memblokir akses remote MySQL dari luar server demi alasan keamanan jaringan utama.
2. Seluruh logika server disatukan dalam satu berkas tunggal (`server.js`) tanpa pemisahan tugas.
3. LiteSpeed (`lsnode`) atau Phusion Passenger cPanel secara otomatis menumbuhkan (*scaling*) jumlah proses Node.js baru tanpa batas atas yang aman untuk melayani pengunjung.

### Solusi
1. **Penyederhanaan Alur .env (Standard dotenv)**: 
   - Mengembalikan pemuatan lingkungan ke cara bawaan standar industri yang paling handal: **`require('dotenv').config()`**.
   - *Alur Kerja:* Menggunakan satu berkas `.env` utama di root folder. Pengguna cukup menyalin (*copy-paste*) isi konfigurasi `.env.local` (untuk pengujian lokal) atau `.env.production` (untuk deploy cPanel) secara langsung ke dalam `.env` utama sebelum dijalankan. Cara ini 100% kompatibel di cPanel tanpa membutuhkan hak akses/izin sistem khusus yang rumit!
2. **Otomatisasi & Proteksi Database**: Menambahkan logika auto-create database (`CREATE DATABASE IF NOT EXISTS`) sebelum inisialisasi pool database. Logika kueri dibungkus dengan `try...catch` agar kesalahan kueri "Access Denied" (yang wajar terjadi di cPanel akibat keterbatasan hak akses user) diabaikan secara halus tanpa menghentikan startup aplikasi.
3. **Rombak Folder Modular (MVC/Router-Based)**: Merestrukturisasi proyek secara total dengan mengelompokkan kode ke dalam folder `src/`. File `server.js` di direktori utama diringkas dari 442 baris menjadi **38 baris** yang sangat bersih dan rapi.
4. **Limitasi Proses cPanel & PM2**: 
   - Membuat berkas `.htaccess` cPanel untuk membatasi Phusion Passenger agar hanya menjalankan maksimal 1 proses Node.js (`PassengerMaxPoolSize 1`). Ini memastikan real-time SSE tersinkronisasi sempurna dan aman dari batas proses.
   - Menyediakan berkas `ecosystem.config.js` untuk PM2 lokal agar berjalan stabil menggunakan 1 proses tunggal di mode `fork`.
5. **Sanitasi Direktori Utama**: Memindahkan semua file kueri uji coba, file log lama, dump database SQL lama, dan file backup ke direktori baru `arsip/` agar repositori utama sangat bersih.
