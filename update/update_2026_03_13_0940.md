## 2. 📱 1 HP = 1 Lokasi Saja (Anti Spam)

**Masalah**: Satu HP bisa ambil antrian di 2 lokasi bersamaan → terjadi spam antrian atas nama yang sama.

**Solusi**:
- Saat ambil antrian, simpan `device_id` (fingerprint unik per browser) ke localStorage & kirim ke server
- Backend cek: jika `device_id` sudah punya antrian aktif (waiting/called) di **lokasi manapun**, tolak pendaftaran baru
- Client-side juga cek localStorage `my_queue_id` lintas lokasi (bukan per-lokasi)
- Ubah localStorage key menjadi global (bukan per-lokasi) supaya 1 device hanya bisa 1 antrian aktif

---

## 3. ❌ Cancel → Nomor Hilang & Nomor Selanjutnya Naik

**Masalah**: Saat nomor di-cancel, nomornya tetap ada dan tidak bergeser. Nomor selanjutnya tidak naik/maju.

**Solusi**:
- Saat antrian di-cancel, re-assign `queue_number` semua antrian yang masih `waiting` agar berurutan kembali
- Backend: setelah cancel, query semua antrian waiting di lokasi itu, lalu update nomor urutannya
- Broadcast update ke semua client agar tampilan langsung berubah

---

## 4. 📋 List Antrian Nama di Admin Dashboard

**Masalah**: Admin tidak bisa lihat siapa saja yang sedang mengantri.

**Solusi**:
- Tambah section baru di admin dashboard: **"Daftar Antrian"**
- Tampilkan list nama + nomor antrian + jumlah sesi + status
- Data di-update realtime via SSE
- Tambahkan endpoint API baru: `GET /api/queue/list/:location` untuk ambil daftar antrian
- Admin bisa cancel antrian langsung dari list
